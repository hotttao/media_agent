# Agent 资源管理与配置交互

## 入口与边界

企业资源库与个人模型连接由 Settings 左侧导航访问。企业选择来自 Auth 当前有效成员列表；Prompt、Skill、MCP 分别显示真实可见目录。Workspace Settings 继续作为既有单实例 App，统一承载配置及管理内容；无 Workspace 时使用同一 Settings 视图，旧 `/library/:organizationId?` 和 `/model-connections` 兼容访问。

资源库和 Settings 沿用已确认 Penpot Agent 项目及 Workflow 的暖浅背景、白色面板、深色主按钮与黄色重点。资源列表与内容编辑器并列，窄屏通过返回列表切换；表单和历史使用可滚动区域，主要操作始终可达。界面称系统默认指引，不暴露 Platform Prompt 模板装配细节。

## 资源旅程

Prompt：当前企业列表 → 新建默认私有 → 编辑正文/名称 → 查看固定历史 → 明确回滚为新版本。owner 可编辑授权及归档，editor 编辑内容，viewer 读取；没有权限时不显示可提交的修改动作，服务端拒绝仍作为最终事实。

Skill：选择在线创建、ZIP/tar.gz 上传或 Git 导入 → 文件树编辑草稿 → 校验并明确发布 → 发布历史浏览/下载。Git 凭据为写入式密码字段，留空保留、明确清除才能删除；不放入 URL、localStorage 或日志。手动同步和发布均提示尚未改变任何 Agent 的固定选择。二进制只下载，不以文本覆盖。删除文件、丢弃草稿、回滚和归档均展示具体目标后确认。

资源授权：私有、指定部门、企业可见三选一；部门 viewer/editor 在同一企业范围选择，owner 保存时带当前 expected_version。当前 Auth 仅提供所属部门列表，是否开放企业有效部门名称查询正在单独确认；在确认前不扩大读取范围。

MCP 目录：企业 admin 登记/编辑本企业外部 HTTP/SSE MCP，平台 admin 可维护平台定义；普通成员只查看授权列表。认证类型为无、Bearer、API Key、OAuth，目录不填写秘密。Workspace Settings 创建绑定并配置写入式凭据、启停与固定定义版本。OAuth 使用 Auth 弹窗授权，校验 postMessage origin 与来源窗口，完成后重新请求连接状态；断开需要确认，不把回调消息当作已连接事实。

## 明确确认 Agent 配置

Prompt 不设置、直接填写、引用资源库三种方式互斥；库选择包括固定版本。Skill 只能选发布版本，MCP 选择绑定的固定版本。保存前展示来源与版本变化，用户明确确认后提交 Control expected_version/idempotency_key。保存成功刷新权威 Workspace 与选择信息，不自动修改当前会话。

已有会话保持原配置并继续使用；界面可提示当前选择已有更新，并提供新建会话入口，不能因仅元数据版本变化阻止发送。Agent 类型发生变化时，新执行使用新会话，原历史保留。保存失败保留输入并展示可重试/重读操作，409 要求重新加载后确认，不能自动覆盖。

新建会话期间由当前 Workspace 页持有创建中状态，禁用重复创建并显示 Agent 启动提示。Gateway 等待同一 Session 的运行实例注册；超时返回可重试错误，保留服务端 starting 记录。切换 Workspace 后忽略旧请求的成功或失败结果，不写入新 Workspace 的 Session 列表或错误。

## 状态与保密

组织、列表、详情、历史和文件请求均有加载、空态、失败与重试。企业切换会清除选中项、草稿和秘密字段，取消/忽略旧请求结果。未授权、归档、已停用和未发布是不同状态，不以空列表替代错误。

资源事实、版本、ACL、凭据是否配置归服务端；表单、未保存文件、列表筛选和秘密仅在当前组件内存。公开浏览器接口不读取内部代理凭据端口。窗口关闭和成功保存后清空秘密，网络失败不打印请求体。前端操作可见性不替代 Workspace manage 或服务端资源授权。

## 验证

组件验证企业/部门选择、只读权限、互斥 Prompt 来源、固定版本选择、秘密清空与冲突。浏览器验证资源创建编辑、Skill 导入/发布、MCP 配置、明确更新以及旧会话继续使用。后端真实 HTTP/数据库检查与浏览器替身场景分别记录，正式 Docker/模型使用另行验收。

## 个人模型连接

Settings 的个人分区提供“模型连接”入口。个人连接列表与企业目录分离，只能查看本人连接；导入 auth.json 文件后显示名称、类型、状态和版本，无原文预览、下载或复制。编辑可仅改名称或上传新文件，写请求 expected_version 防止覆盖；撤销须确认，失败保留输入，完成清空文件内容。新用户默认名称“本机 Codex”，不自动读取浏览器或服务器文件。

Workspace 创建/编辑可选择 API Key 或个人 Codex 连接；后者需明确选择，提示绑定后 Workspace 执行者可使用模型但无法查看凭据。保留未修改的选择；切换 Agent 类型后清空不适用的连接。保存连接变更生成新执行配置，沿用现有固定元数据；原 Session 保持原连接，界面进入新会话。连接管理在 Settings 内展示，个人归属不随 Workspace 切换改变。

旧 Session 固定配置版本落后于当前 Workspace 时，聊天区显示两个版本及明确的新建会话入口；不因版本落后禁止旧会话继续执行。恢复仅解除暂停，不替换原模型连接、元数据或重放失败输入。新建成功后切换新 Session，旧历史保持可访问；创建期间禁用重复提交，失败保留旧 Session 并显示错误。模型认证提示明确针对会话固定配置，不能让用户误以为当前 Workspace 的有效连接失效。

## Settings 导航与滚动

Settings 左侧分为工作空间（概览、Agent配置）、企业资源（Prompt、Skill、MCP目录）、个人（模型连接）。选择企业资源时显示有效企业选择器与企业范围；个人连接明确为当前用户所有。顶部 Menubar 只提供统一 Settings 入口，不再并列资源库/模型连接。Workspace Agent配置里的资源库操作在同一Settings内部切换，保持当前Workspace和Session。

`?settings=` 表示Workspace内活动分区，保留 `?session=`。无Workspace时 `/settings/:section?` 使用同一视图，工作空间分区不可用；旧 `/library/:organizationId?` 与 `/model-connections` 兼容进入统一导航。切换Workspace清理分区和资源草稿，不复制秘密到路由或持久化状态。

Settings 根容器占满Slot，导航固定，内容视口位于右侧外缘。仅内部阅读容器限制宽度；表单长内容不会让滚动条停在Slot中央。狭窄Slot以容器断点切换分区选择器；资源列表/详情也按可用容器宽度适配。切分区会卸载原表单并清空未保存秘密，服务端已保存数据重新加载；不自动提交或丢弃已保存配置。保留加载、空态、失败重试、只读权限和确认操作。

Claude Code/Goose的Workspace表单提供模型协议、名称与API基础地址；Goose必须明确模型名。原有API Key只写不回显，切换Agent/协议清空草稿，保存更新遵循新Session/旧配置保留规则。Codex个人连接选择不变。
