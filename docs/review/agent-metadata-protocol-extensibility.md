# Agent 元数据通知协议扩展性 Review

日期：2026-10-11。范围：消息协议与关联设计，不是代码实现一致性审查。结论：原稿扩展性不足，已修订协议；结果上报已确认采用 API；统一响应 schema、实例计数与部署兼容仍未完成。

## 发现与处理

| 级别 | 原稿问题 | 具体扩展场景 | 修订/状态 |
|:---|:---|:---|:---|
| P1 | 封套字段绑定单一 Control 配置消息 | 新业务服务增加不同元数据通知，需要改变全部协议 | 已分离封套、scope、type 和 data_version；当前更新生产权不变 |
| P1 | 未知 kind 直接失败，与 changes 只作提示矛盾 | 新增资源类型时旧 Agent 无法处理已能加载的配置 | 已将 changes 改为可选提示，未知提示忽略，完整配置按统一 schema 校验 |
| P1 | 不回退混淆旧通知与用户显式回滚 | 用户明确从 Skill v7 回滚 v5，被误判旧版本 | 已增加选择序号，与资源版本及不透明配置引用分离 |
| P1 | 串行消费不能覆盖准备配置期间又有新选择 | A 正在下载旧目标时 B 已成为当前选择 | 已增加应用前权威核对与本机选择序号单调提交；说明最终一致窗口 |
| P1 | 只靠启动/重连补查，在线漏通知可能一直不收敛 | Control 提交后未发通知，Agent 连接未断 | 已增加仅针对已确认选择的周期对账，不自动升级目录资源 |
| P1 | 通知兼容、加载实现与结果观测边界不清 | 新配置结构加载失败；多 Pod 一部分成功 | 统一响应 schema；平台代码负责版本化与 Runtime 适配，结果经 API 上报，具体 IDL 待定 |
| P2 | 单独 event_id 假设所有生产方全局唯一 | 新服务重用了另一个服务的本地 ID | 已按 source/event_id 去重并限制生产权限 |
| P2 | 扇出与重投稳定 ID 规则未区分 scope | 一个资源影响两个 Workspace，被误去重 | 已定义每 scope 独立 ID、同消息重投不变 |
| P2 | 协议版本与业务数据格式同一版本 | 仅一个 type 增加必填数据导致全协议升级 | 已分离封套主版本与按 type 的数据主版本 |

## 场景核验

| 场景 | 必须行为 | 文档核验 |
|:---|:---|:---|
| 新增可选变化提示 | 老 Agent 继续拉取已支持完整配置 | 已明确 |
| 配置响应主版本不兼容 | 保留旧配置并报告 incompatible，系统按部署兼容窗口升级加载代码 | 已明确，配置响应 IDL 待定义 |
| 选择序号18投递晚于19 | 不降低实例已应用序号 | 已明确 |
| 用户把资源7回滚到5，选择序号升到20 | 允许回滚，不当作过期消息 | 已明确 |
| 两实例共享卷且状态不同 | 共享不可变产物，实例状态独立，不互相覆盖指针 | 已明确，Runtime 实现待验证 |
| Gateway 请求经过另一个实例 | 直接代理权威查询，无控制配置缓存 | 已明确 |
| 实例新代次收到旧代次结果 | 旧结果不覆盖当前实例投影 | 已明确，结果传输待定义 |
| 在线漏通知但没有重连 | 周期查询已确认选择收敛 | 已明确，周期参数待定义 |
| 有资源目录新版本但用户未确认 | 不能因通知、补查或重试自动升级 | 已明确 |

这里只验证设计规则能够覆盖场景；未执行消息或 Runtime 集成测试，不把文档审查当作实现验证。

## 未决项

1. 已确认结果经 Gateway API 上报 Control；仍需固定 IDL、当前参与实例集合、排空/离线计数与部分成功等待规则。
2. 统一配置响应 schema 与系统部署的协议兼容窗口。
3. 多副本共享文件的原子发布、版本保留/回收，以及 Codex/Claude Code 的旧 Session 隔离实现。
4. 队列生命周期、延迟重试/隔离和周期对账的部署参数。

这些是进入实现前的具体契约缺口；不能据此宣称整个设计和实现已完成。

## 2026-10-11 · 职责纠正

撤销此前将 Skill 版本化定义为实例可选能力的建议。版本选择、产物发布与旧 Session 隔离是系统职责；不新增 metadata_capabilities/required_capabilities。版本兼容限于消息/响应契约与部署实现，不把业务不变量交由 Agent 自报是否支持。
