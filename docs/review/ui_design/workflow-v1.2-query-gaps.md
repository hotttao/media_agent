# v1.2 UI 后端查询与宿主支持缺口

## 范围

只列当前工作流、模板、素材 UI 所需支持。不扩展 Agent Token、Provider 实现、Conductor 调度或历史迁移。UI 使用已有命令接口；以下内容不能靠展示代码伪造。简单分页、名称搜索、部门查询和对象引用解析已经接现有接口，不是新增后端需求。

## 需统一对齐

| 支持项 | 已核对事实 | 当前交互 | 建议后续支持 |
| --- | --- | --- | --- |
| 冻结工作流版本读取 | Workflow 公开读取以头版本为主，Job 固定 workflow_version；不能拿新拓扑替代旧执行 | 同版本显示图；不同时显示真实 StepRun 列表并解释缺口，恢复/重跑契约不可读时禁止提交 | 按 workflow_id/version 查询冻结步骤、派生 input_schema、模板引用；必须沿用原授权 |
| 有效操作权限 | 可读资源不意味着可编辑、发布或授权；created_by 与当前用户能证实 owner，但不能完整表达 editor | 发布/共享仅可证实 owner 提供入口；命令仍由后端授权 | 资源详情返回由现有策略计算的 allowed_actions，不由 UI 推导组织管理员万能权限 |
| 授权列表及目标部门 | /api/teams 返回当前用户可查询的部门，不是企业完整部门目录；资源读接口没有完整 grants | 明确说明列表范围；指定同企业部门后提交 grant/revoke，不伪造完整共享状态 | owner 可读取授权记录与可授权目标部门；部门生命周期及授权边界由后端判定 |
| Capability 目录 | 编辑器有已定义契约的 Key/版本，但缺少可用版本目录读接口 | 手工填写明确版本并检查结构；不提供假能力选项 | 授权范围内列出版本、平台/生成方式/类型、execution_target 及参数契约 |
| 当前轮审批的跨窗口前置条件 | 命令有幂等键，公开契约没有 expected generation/round；最新 review 可能属于旧轮 | 使用不可变候选对象指纹保留选择、请求意图和 pending 回执；这是本地 UX 保护，不是分布式前置条件 | 如需要拒绝跨窗口旧轮提交，先对齐原生运行轮标识与业务契约，不能仅添加 UI token |
| 生成历史 | 现有 GeneratedAsset 是已接受产物；不能当成全部候选轮次审计 | 节点显示当前返回的候选和真实结果，产物页显示来源 | 若需完整轮次历史，单列只读模型与保留策略，不用 retry_count 推算生成次数 |
| 商品到工作流的跨 App 启动 | HostShim 已提供可选 Navigation Port；standalone 向目标 Slot 实例投递类型化启动意图，plugin 转发宿主提供的端口 | 商品详情选择同企业、同 Scope、已注册且含 Product 输入的 Workflow，运行表单预填但不提交；缺端口时提示手工路径 | media_platform 实际企业上下文和 Navigation Port 仍需宿主接入验收；不冒充 fixture 已完成真实集成 |

## 性能排查记录

真实执行详情 E2E 首次 GET /jobs?page=1&page_size=20 达到 30 秒请求超时。已读 `media_workflow/biz/service/job/service.go`：List 对含 ConductorWorkflowID 的每个 Job 顺序 reconcile 并重新读取记录。该串行读路径是待验证的延迟因素，尚不能仅凭一次超时认定根因。测试诊断请求放宽至 120 秒；这不是生产性能修复，也不改变 Conductor 作为运行状态权威的边界。

复测执行详情约 2.6 分钟通过，任务列表等待仍明显。前端另查到可直接纠正的请求放大：定义详情原本默认读取最多 100 条执行，并在未打开执行列表时逐项持续查询。已改为打开列表才读取/轮询；任务列表使用最新快照状态、10 秒核对并在终态停止。没有修改后台状态同步或 Conductor 调度行为，不能据此宣称 API 延迟已经解决。

## 完成判定

页面已接入某个 API 不等于完成真实业务写入验收；只读借用数据测试不替代新建/保存/发布/运行/审批闭环。复杂后端查询未擅自实施，后续集中 review 时确定范围。简单宿主可选 Navigation Port 已按既有 ADR 实现，真实平台接入仍另行验收。
